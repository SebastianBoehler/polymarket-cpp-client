# v3.0.0

This release adds authenticated user streams and on-chain position operations.
It also defines the contributor and coding-agent workflow.

## New APIs

- `UserStream` receives typed CLOB order and trade events for selected markets
  or all markets. Subscriptions replay after reconnect. Gap callbacks mark local
  state stale; recovery callbacks let callers reconcile through REST after the
  subscription is restored. Authentication rejection stops the stream, and a
  connection timeout stops the transport.
- `PositionClient` splits, merges, batch-merges, and redeems binary positions
  from an EOA or a Gnosis Safe. It supports CTF and Protocol V2 contract paths,
  including 31-byte V2 market IDs.
- Solidity ABI encoding, EIP-155 transaction signing, transaction JSON-RPC
  helpers, and `PolymarketContracts` are available as public building blocks.
- `TransactionHandle` tracks submission and mined outcomes. `PartialBatchError`
  preserves submitted EOA hashes, the failed call index, and the original cause.
  Waiters handle timeouts shorter than the polling interval.
- `user_stream_example` and `position_example` show the new workflows.

## Requirements and limits

This is a major release because public include paths changed. Replace flat
includes such as `<http_client.hpp>` and `<types.hpp>` with
`<polymarket/http_client.hpp>` and `<polymarket/types.hpp>`. All SDK headers now
install under `include/polymarket/`, avoiding collisions with generic application
headers. No forwarding headers are installed at the old paths. Use a clean install prefix;
installing over v2 does not remove previously installed flat headers.

The CMake target remains `polymarket::client`. Rebuild consumers against matching
v3.0.0 headers and libraries because public type layouts also changed.

EOAs pay Polygon gas themselves. Safe operations use the Polymarket relayer and
require `RELAYER_API_KEY`. Safe batches are atomic; EOA batches can complete
partially. A timeout does not mean a transaction failed.

Position operations use integer base units and do not set approvals. Configure
the required token approvals first. `POLY_PROXY`, `POLY_1271`, combo positions,
and lookup by market or position ID are not supported. Split and merge use
open markets returned by Gamma. See
[the position guide](https://github.com/SebastianBoehler/polymarket-cpp-client/blob/v3.0.0/docs/position-operations.md).

## Development and validation

`AGENTS.md`, `CONTRIBUTING.md`, protocol guidance, and a release checklist define
scope, coding rules, commit names, verification, and publication boundaries.
Pinned clang-format, clang-tidy, and Prettier checks enforce formatting and
selected correctness, performance, and naming rules on changed code. PR titles
follow Conventional Commits, and PRs report commands and evidence.
Release notes are versioned with the source and required by the release workflow.

Deterministic tests cover ABI/signing vectors, local RPC/Gamma/relayer flows,
stream lifecycle, partial batches, and deadlines. Release packages are gated on
Linux x86-64 and macOS arm64 builds, offline tests, and installed-package consumer
checks. Protocol V2 position flows have fixture coverage; the contributor did
not report a live V2 market test. No funded transaction is part of release CI.
