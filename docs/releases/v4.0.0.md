# v4.0.0

This release adds typed Gamma and Data API clients, public RTDS and Sports
streams, reusable pagination, and trading setup and order-flow helpers.
It includes all changes since v3.0.0.

## Migration and compatibility

This is a major release because the string-based `ClobClient` constructors now
reject chain IDs other than 137. `ClobClient(url, 80002)` throws instead of
signing against production exchange addresses with a different chain ID.
Use an `Environment` with explicit endpoints and contracts for another
deployment. A string constructor changes only the production CLOB host.

Rebuild consumers and shared plugins against matching v4 headers and libraries:
several public layouts changed, including client, config, transport option,
statistics, contract, and error types. Namespaced headers and the CMake target
`polymarket::client` are unchanged. Update CMake package requirements from major
version 3 to 4 where specified. See the [migration guide](https://github.com/SebastianBoehler/polymarket-cpp-client/blob/v4.0.0/docs/migration.md#v4).

`Environment::production()` and `preproduction()` select endpoints and contracts
together. `Config::for_environment()` and
`PositionClientConfig::for_environment()` configure streams and positions from
the same deployment. Preproduction is not a testnet: it uses Polygon mainnet
and production contracts, so orders and on-chain operations can use real funds.
API credentials are per environment.

## Data and discovery

- `GammaClient` provides typed market and event discovery, lookups by ID, slug,
  or URL, tags, series, sports, teams, search, comments, and public profiles.
  Market lists skip non-binary markets. Position market resolution now uses
  Gamma's keyset endpoint.
- `DataClient` covers trades, wallet activity, positions, portfolio value,
  statistics, PnL, user volume, accounting snapshot downloads, holders, open
  interest, live event volume, price history, resolutions, and leaderboards.
  Data amounts use `double`; rows preserve their raw JSON.
- `Paginator<T>` supports cursor, offset, keyset, and page-numbered APIs through
  `next_page()`, bounded collection, range iteration, and resume tokens.
  CLOB pagers expose markets, open orders, trades, and position lists. Inspect
  `error()` after iteration and `truncated()` when an endpoint's offset cap is
  reached. Items fetched before an error are retained.

## Public streams

- `SportsStream` delivers typed live game results, answers server text pings,
  and reconnects after 30 seconds without frames.
- `RtdsStream` combines comment, reaction, Binance and Chainlink crypto-price,
  Chainlink 30/60-second TWAP, and Pyth equity-price subscriptions. Server
  subscriptions are shared, diffed while connected, and replayed on reconnect;
  per-subscriber filters run locally. Full-accuracy string prices preserve
  decimal precision, including exact scaling of Chainlink's 18-decimal integers.
- Both streams report gaps and recovery. Malformed Sports updates and malformed
  RTDS events on supported topics report parser errors and trigger recovery.
  RTDS stops further subscriber delivery when a callback stops the stream.
  These public feeds do not replay missed events; reconcile application state
  through REST when needed.
- `WebSocketOptions` adds configurable text pings, server-ping replies, and an
  idle reconnect timeout. Existing CLOB heartbeat defaults are preserved.
- Gamma comment parsing now accepts integer-string `positionSize` values.

RTDS's authenticated v2 price service and `activity` topic are not included.
The official SDKs deprecate the included RTDS price topics in favor of the
authenticated price service.

## Trading and wallet setup

- `PositionClient::get_trading_approvals_state()` reads missing token approvals.
  `setup_trading_approvals()` grants only those still missing, using the shared
  approval set from `required_trading_approvals()`. Low-level ERC-20 approval,
  ERC-1155 operator approval, and ERC-20 transfer helpers are also available.
- `estimate_market_price()` simulates fills from REST or an existing book.
  `place_limit_order()` supports GTC/GTD and post-only orders;
  `place_market_order()` supports FAK/FOK and worst-price bounds. Book-priced
  FOK orders reject insufficient liquidity before signing.
- `get_trade()` and `wait_for_order_fill_settlement()` track terminal fill
  status and final transaction hashes. Confirmations without hashes reconcile
  through REST and remain pending until final hashes arrive. Earlier MINED or
  order-response hashes are not reused as final settlement evidence.
- Rate-limited reads retry HTTP 429 up to twice using `Retry-After`, with a
  five-second maximum accepted delay. Writes are never retried automatically.
  Rate-limit listeners expose server headers and enforcement warnings.
- `SdkErrorCode` adds `InsufficientLiquidity`, `Timeout`, and
  `TransactionFailed`; update exhaustive switches.

EOAs pay Polygon gas. Safe operations use the relayer and require
`RELAYER_API_KEY`. Safe batches are atomic; EOA batches can complete partially.
Approval setup grants maximum ERC-20 allowances and ERC-1155 operator access
to the configured contracts, including the perps deposit spender. That approval
does not add perps trading support. Position operations still support EOA and
Gnosis Safe wallets, not `POLY_PROXY`, `POLY_1271`, or combo positions. See the
[position guide](https://github.com/SebastianBoehler/polymarket-cpp-client/blob/v4.0.0/docs/position-operations.md) and [order-flow guide](https://github.com/SebastianBoehler/polymarket-cpp-client/blob/v4.0.0/docs/order-flow.md).

## Networking and request behavior

- REST and WebSocket connections support HTTP/HTTPS/SOCKS proxies and interface
  binding through `set_default_network_route()` or per-client options.
  Configured routes fail closed. Geoblock checks can reuse an HTTP client.
- HTTP responses can be compressed. Book responses seed tick-size and neg-risk
  caches; off-grid prices invalidate only the tick cache. Market discovery reuses
  Gamma clients. These changes remove redundant requests and connection setup.
- Orderbook parsing and signing avoid unnecessary copies and allocations.
  HTTP heartbeats no longer affect connection statistics or last-request
  metrics. Explicit tick sizes use cached minimum validation when available;
  otherwise the server validates them.

See the [networking guide](https://github.com/SebastianBoehler/polymarket-cpp-client/blob/v4.0.0/docs/networking.md) for route configuration and limits.

## Validation and evidence limits

The offline suite covers local HTTP/RPC/relayer fixtures, pagination, parsing,
stream recovery, callback shutdown, and installed-package consumers. ASan/UBSan
and libFuzzer checks cover REST and WebSocket parsers. Release publication is
gated on Linux x86-64 and macOS arm64 package builds and offline tests.

Local release preparation passed 84/84 offline tests on macOS arm64 in Release,
including the installed-package consumer and both fuzz corpus replays. A
separate installed-package consumer linked the new clients and streams,
verified version 4.0.0, and checked the chain-80002 rejection without network
requests. The migration example compiled against the release headers.

Contributors reported read-only live checks for production and preproduction
CLOB reads, book estimates, routed streams, Gamma and Data API responses,
Sports updates, and RTDS comments and crypto prices. Equity stream updates and
history, removed comments, and Sports finish timestamps have fixture coverage
only. The preproduction Gamma, Data API, and relayer were not validated live.
Order placement and settlement helpers have local fixture coverage; release
validation does not place orders or move funds. An approval setup transaction
was separately reported by the contributor, not executed by release CI.

Thanks to Bill Luo (@yluoc) for the trading approvals, environment support,
rate-limit handling, order-flow helpers, parsers, pagination, data clients,
and public streams.
